## 校对入口

1. 打开任一城市 md 的 **§12 校对待办**，那是机器已识别的问题清单。
2. 全量机器校验：`python tools/validate_data.py`（10 项规则，含表格列数、粗体配对、悬空引用、评级口径、维度完整性）。
3. 补采单城：`python tools/amap_collect.py --city XX市`（wave1+2 约 63 请求）；只补新维度：`--city XX市 --wave 2`（约 14 请求）。**跑批前先探测 key 可用性。**
4. 重渲染：`python tools/render_md.py --all`；重建索引：`python tools/build_index.py`。

## 数据口径与已知边界

- **评分**取高德 `biz_ext.rating`，无人工干预；无评分者一律 ⚠️，不做无据推荐。
- **人均**取高德 `biz_ext.cost`，单位元，可能滞后于实际涨价。
- **商圈画像分两类**：可推导的（载体类型/消费带宽/动线主轴/业态分布）直接给出；不可推导的（高峰时段/本地客成分/可跳过商业段）标「待人工校对」，不编造。
- **商圈评级判据可复算**：S/A/B/C 的量化门槛写在各城 §2 表头。
- **图片**取高德店铺图 URL，仅供校对时肉眼确认门店真实性。
- **苍蝇馆不做无据判定**：小店语义 + 评分区间双条件，宁可漏列也不编造。
- **关联为机器初判**：仅靠距离的关联必须人工确认，防止景区边界、跨街区误配。
- **撤柜风险**：§4 场内儿童游乐的撤柜率高，去之前需二次确认营业状态。
- **村级数据缺失**：高德行政区划接口不下探到村，本库不含村级名录，亦未编造。

## 采集纪律（事故沉淀）

1. **先探测 key 再跑批**：高德 key 可能配 IP 白名单，表现为 `INVALID_USER_IP`（10005），重试无效、不会自愈。探测命令见 SKILL.md §6.7。
2. **限速**：默认单请求 0.6s、城间 2s、每 100 请求长休 10s。宁可慢，不可错——错误的空结果比慢更致命。
3. **全查询面 0 条 = 接口故障**，不得当作「该城无数据」落盘。
4. **多 key 池**：`keys.txt` 多行，主 key 被拒自动切换，成功后恢复。
5. **预算硬闸**：`--budget` 必给，防打爆日配额。
